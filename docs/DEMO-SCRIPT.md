# Сценарій демо-відео

Ціль — 2–5 хвилин. Показати запуск і обидві фічі, з наголосом на тому, за що оцінюють:
**захист від подвійного нарахування, від'ємних сум і повторного скасування**.

## Перед записом

```bash
php artisan migrate:fresh --seed   # чиста БД: два гравці, чотири промокоди
php artisan serve --port=8000      # термінал 1
npm run dev                        # термінал 2
```

- Вкладка на `http://127.0.0.1:8000/`, вийти з акаунта (щоб почати з форми логіну).
- Другий термінал видно на екрані — знадобиться для показу тестів.
- Масштаб браузера ~125%, вікно на весь екран: у записі має читатись баланс і статуси.
- Пароль обох гравців — `password`, дані є в README.

## Що показати обов'язково

1. **Баланс до і після** кожної операції — у кадрі, не «повірте на слово».
2. **Повторний claim** і **повторний revoke** — саме вони показують захист від зловживань.
3. **Різницю 422 і 409** — це прямий пункт умови (окрема помилка з чіткою причиною).
4. **Модалку підтвердження** — власну, не `window.confirm`.

## Якщо лишається час (запасні 30–60 с)

- **Ізоляція гравців:** вийти, зайти як `ihor@example.com` — баланс 125.50, історія порожня,
  той самий `WELCOME100` йому доступний.
- **Чужий claim → 404, не 403** (через `curl` або DevTools): відповідь не підтверджує факт
  існування чужого запису.
- **`SchemaGuardsTest`** окремим прогоном: пише напряму в БД, повз сервіси — доводить, що
  інваріанти тримаються на схемі й переживуть помилку в коді.
- **Нестача балансу:** якщо бонус уже витрачено, revoke відхиляється з `insufficient_balance`,
  баланс у мінус не йде і статус не змінюється.

## Чого не робити в кадрі

- Не показувати `.env` і токени.
- Не гортати код рядок за рядком — показуємо поведінку, код лише там, де він пояснює рішення
  (`WalletService::apply()` і міграція з unique-індексами — цього досить).
- Не вибачатись за скоуп: реєстрація, ролі, ліміти використань свідомо поза скоупом,
  перелік — у `docs/PLAN.md`.
